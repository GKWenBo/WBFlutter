# 99 · 踩坑清单

> 使用说明：每条按「现象 → 原因 → 解法」写。内容随课程推进持续追加，遇到新坑先记在这里，再决定要不要改代码。

## 一、工程与工具链

### 1. 一运行就崩：`No ProviderScope found`

- **现象**：启动即抛 `StateError: No ProviderScope found`。
- **原因**：provider 实例挂在 `ProviderScope` 上，不是全局变量；没有 Scope 就没有容器。
- **解法**：`main()` 最外层包一层；widget 测试里 `pumpWidget` 同样要包。

```dart
runApp(const ProviderScope(child: RiverpodLabApp()));
```

### 2. 改了 `@riverpod`，分析器还是报 `xxxProvider` 未定义

- **现象**：`The name 'appVersionProvider' isn't defined`。
- **原因**：provider 是生成出来的，`.g.dart` 没生成或生成失败。
- **解法**：`dart run build_runner build`；还不行就 `clean` 后重新 build。开发时建议常驻 `build_runner watch`。

### 3. `--delete-conflicting-outputs` 已经没用了

- **现象**：build_runner 输出 `These options have been removed and were ignored: --delete-conflicting-outputs`。
- **原因**：build_runner 2.15 起移除了这个参数（它是 2.x 时代所有教程的标配命令）。
- **解法**：直接 `dart run build_runner build`；生成物错乱时 `dart run build_runner clean` 再 build。

### 4. 不要手改 `.g.dart`

- **现象**：改完下次生成被覆盖，或 IDE 里出现重复定义。
- **原因**：生成物每次 build 都会整体重写。
- **解法**：只改源文件。需要自定义 provider 名时用 `@Riverpod(name: 'xxx')`，而不是改生成物。

### 5. 分析器不要检查生成物

- **现象**：`flutter analyze` 报生成代码的风格问题，或者提示 `.g.dart` 里的 lint。
- **原因**：生成代码不遵循项目 lint 规则。
- **解法**：`analysis_options.yaml` 里 `exclude: ['**/*.g.dart']`（本工程已配置）。

### 6. `part` 指令和文件名必须对上

- **现象**：生成失败，提示找不到 part 文件。
- **原因**：`part 'app_info.g.dart';` 要求生成物与源文件同目录、文件名严格对应。
- **解法**：源文件叫 `app_info.dart`，part 就必须是 `app_info.g.dart`；源文件改名时记得一起改。

## 二、API 行为类

### 7. codegen 默认 autoDispose，和手写版相反

- **现象**：页面弹出后状态被清空；换成手写 `NotifierProvider` 时却会保留。
- **原因**：`@riverpod` 生成的 provider 是 `isAutoDispose: true`（见 `app_info.g.dart`），手写默认常驻。
- **解法**：需要跨页面常驻时用 `@Riverpod(keepAlive: true)`；其余情况让它自动销毁更省内存。

### 8. `StateProvider` / `StateNotifierProvider` 找不到了

- **现象**：2.x 教程里的 `StateProvider` 编译不过。
- **原因**：3.0 起这两个 API 被移到 `package:flutter_riverpod/legacy.dart`。
- **解法**：新代码用 `Notifier` / `AsyncNotifier`；迁移老代码时再 `import 'package:flutter_riverpod/legacy.dart'`。

### 9. 失败的 provider 会自动重试

- **现象**：网络请求失败后没点「重试」，过一会儿页面自己好了；或者错误页只闪了一下。
- **原因**：Riverpod 3 默认对失败的 provider 做指数退避重试（200ms 起，最多 10 次；`Error` 和 `ProviderException` 不重试）。
- **解法**：需要确定性时在 `ProviderScope(retry: (count, error) => null)` 关掉，或在单个 provider 上声明 `retry`。教学和测试里建议关掉。
