## Task 1：C 核心

- 定义错误码 `0 / 1001 / 1002 / 1003 / 1004`。
- API：`version` / `init` / `init_demo` / `hmac_sha256_hex` / `fingerprint_hex` / `crc32` / `last_error` / `warmup`。
- 所有权：输出缓冲区由调用方分配；原生只写不持有。
- `last_error` 用 `_Thread_local char[256]`；密钥状态进程级。
- 已知向量（宿主编译验证）：
  - RFC 4231 Test Case 2 → `5bdcc146bf60754e6a042426089575c75a003f089d2739839dec58b964ec3843`
  - CRC32(`123456789`) → `0xCBF43926`
  - 未初始化 → 1001；空 message → 1002；out_size 不足 → 1003

```bash
clang -std=c11 -Wall -Wextra -O2 -I src /tmp/harness.c src/nl_sign_kit.c -o /tmp/harness
/tmp/harness
```

## Task 2：Dart 绑定层

- `NlSignBinding` 抽象接口：`version / initialize / hmacSha256Hex / fingerprintHex / crc32`。
- `NlSignException` + `NlSignErrorCode`（1001–1004 映射 C；1005/1006 Dart 侧新增）。
- `FfiSignBinding`：
  - Android `DynamicLibrary.open('libnl_sign_kit.so')`。
  - iOS `DynamicLibrary.process()` → 探活失败再试 framework 路径。
  - 其他平台抛 1005。
  - `toNativeUtf8` + `malloc.free`；`calloc<Uint8>(65)` + `calloc.free`。
  - CRC 先 `calloc<Uint8>(len)` + `asTypedList().setAll` 拷贝。
  - 非 0 返回码读 `last_error` 抛异常。
- `NlSignKit` 门面，构造可注入 binding。

## Task 3：Android 构建

- `android/build.gradle.kts`：
  - `com.android.library`，`compileSdk = 36`，`minSdk = 24`。
  - `ndkVersion = "28.2.13676358"`（与 Flutter 3.44 的 `flutter.ndkVersion` 一致）。
  - `externalNativeBuild.cmake.path = file("../src/CMakeLists.txt")`。
- 空 `AndroidManifest.xml`。
- 无 Kotlin 插件类；`ffiPlugin: true` 只负责打包 `.so`。

## Task 4：iOS 构建（SPM）

- `Package.swift`：
  - product `.library(name: "nl-sign-kit", targets: ["nl_sign_kit"])`。
  - target `nl_sign_kit_c`（C，`publicHeadersPath: "include"`）。
  - target `nl_sign_kit`（Swift，依赖 C + FlutterFramework）。
- forwarder `.c` / `.h` 用相对路径引用插件根目录 `src/`，保证只有一份 C 源码。
- `NlSignKitPlugin.register` 调 `nl_sign_kit_warmup()`，防止静态链接裁剪。
- pubspec：iOS `pluginClass + ffiPlugin`；Android 仅 `ffiPlugin`。
- 不需要改 `AppDelegate.swift`；`GeneratedPluginRegistrant.m` 由 `flutter pub get` 生成。
