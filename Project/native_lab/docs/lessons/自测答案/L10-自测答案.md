# L10 自测答案

对照讲义第六节「自测清单」逐条核对。答案只给要点，细节回讲义对应小节。

## 1. FFI 与 MethodChannel 的三点本质差异 + 适用场景

- **通信方式**：channel 是二进制消息 + codec，异步 Future；FFI 是按 C ABI 直接函数调用，同步。
- **线程**：channel 原生 handler 跑 Platform 线程；FFI 在调用它的 isolate 线程同步执行。
- **代码归属**：channel 双端各写一套桥；FFI 只维护一份 C（外加可选的平台打包配置）。
- 选型：系统能力/权限/原生 UI → channel；既有 C/C++ SDK、性能敏感、需要同步 → FFI。

## 2. Android 的 `.so` 路径

`plugins/nl_sign_kit/src/nl_sign_kit.c`
→ `android/build.gradle.kts` 的 `externalNativeBuild.cmake.path = ../src/CMakeLists.txt`
→ NDK 编译出 `libnl_sign_kit.so`
→ AAR 的 `jni/<abi>/`
→ APK 的 `lib/<abi>/libnl_sign_kit.so`
→ Dart `DynamicLibrary.open('libnl_sign_kit.so')`。

验证：`unzip -l build/app/outputs/flutter-apk/app-debug.apk | grep nl_sign_kit`。

## 3. iOS 为什么用 `DynamicLibrary.process()`，`warmup` 干嘛

- iOS 的 C 代码是**静态链接**进 App 可执行文件的，没有独立 dylib 可 `open`。
- `DynamicLibrary.process()` 等价 `dlsym(RTLD_DEFAULT, …)`，从当前进程的符号表里找。
- 静态链接器默认会裁掉“没人引用”的目标文件；`NlSignKitPlugin.register` 里调用
  `nl_sign_kit_warmup()`，制造一个真实引用，保证 `nl_sign_kit.c` 的目标文件被链接进来。
- 如果团队发的是动态 `.xcframework`，则改用 `DynamicLibrary.open('xxx.framework/xxx')`。

## 4. `lookupFunction` 的 typedef 与写错后果

```dart
typedef _HmacNative = Int32 Function(Pointer<Utf8>, Pointer<Uint8>, Int32);
typedef _HmacDart = int Function(Pointer<Utf8>, Pointer<Uint8>, int);
final hmac = library.lookupFunction<_HmacNative, _HmacDart>(
    'nl_sign_kit_hmac_sha256_hex');
```

Dart 不会校验 C 符号的真实签名；typedef 写错（参数个数、宽度、指针类型）会读错寄存器/内存，
轻则结果错，重则进程崩溃。用固定宽度类型 + `ffigen` + 宿主机已知向量测试来防。

## 5. `toNativeUtf8` / `calloc` / `malloc` 的配对

- `'x'.toNativeUtf8()` → `malloc.free(ptr)`。
- `calloc<T>(n)` → `calloc.free(ptr)`。
- `malloc<T>(n)` → `malloc.free(ptr)`。
- `toDartString()` 只拷贝，不释放；原生返回的静态字符串（如 `nl_sign_kit_version()`）
  不能 free。

## 6. 为什么 `Uint8List` 要先拷进 native 内存

Dart 的 `Uint8List` 是托管内存，GC 可能移动/回收；把它的地址传给 C 会得到悬垂指针。
正确做法：`calloc<Uint8>(len)` 分配，`asTypedList(len).setAll(0, data)` 拷贝，调用后再 free。
本课 CRC 就是这么做的。

## 7. C 错误码如何变成 Dart 异常，`last_error` 为什么要线程局部

- C 返回 `int32_t`，0 成功；Dart 每次非 0 都读 `nl_sign_kit_last_error()`，
  抛 `NlSignException(NlSignErrorCode.fromNative(rc), message)`。
- 多个 isolate 可能在不同线程同时调 FFI；错误消息若用普通全局变量会串台，
  所以 C 侧用 `_Thread_local` 缓冲。密钥状态是进程级共享的，应该只初始化一次。

## 8. FFI 阻塞 isolate + 什么时候用 `Isolate.run`

FFI 是同步调用，执行期间当前 isolate 的事件循环停住；超过一帧（约 16ms）就会掉帧。
本课 2 MiB CRC 只有几毫秒，留在主 isolate；大文件哈希、图像处理、音视频解码应放
`Isolate.run` 或长期 helper isolate。每个 isolate 各自打开库，底层拿到的是同一个原生库。

## 9. iOS Release 符号被裁剪的排查/修复

- `nm -g` / `lipo -info` 看符号和架构是否在。
- 确认有 Swift/ObjC 代码引用 C 函数（本课的 `warmup`）。
- 检查 `DEAD_CODE_STRIPPING`、`STRIP_STYLE`、`-exported_symbols_list`、`-all_load`/`-force_load`。
- 兜底：把库改成动态 framework，用 `DynamicLibrary.open('xxx.framework/xxx')`。
