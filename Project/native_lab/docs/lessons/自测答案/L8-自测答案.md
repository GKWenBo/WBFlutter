# L8 自测答案

**1. module / App / 插件 三者的区别？谁依赖谁？**

- **Flutter App**（L0–L6）：一个完整可独立运行的 App，Flutter 是宿主，`ios/Runner` 是它自带的原生壳。
- **插件**（L7）：一个**可复用的能力包**，自己不能运行，被 App 依赖（`nl_device_kit` 提供设备信息能力）。
- **module**（L8）：一段**可嵌入的 Flutter 内容**，被**原生 App** 依赖并嵌入。它自己也不独立运行（虽然带个 `.ios/` 便于调试）。

依赖方向：Flutter App → 插件；**原生 App → module**。关键区别是 module 场景下**原生才是宿主**。

**2. `install_all_flutter_pods` 做了什么？为什么之后必须用 `.xcworkspace`？**

它把这些都变成 Pod 依赖并配好构建：
- `Flutter.framework`（引擎本体）
- `App.framework`（你的 Dart 代码编译产物）
- module 依赖的**所有 Flutter 插件**
- Debug / Profile / Release 各自的产物路径，以及"构建时先编 Dart、再把产物 embed 进 .app"的 Run Script 阶段。

必须用 `.xcworkspace` 是 **CocoaPods 的通例**：pod install 会生成一个 `Pods` 工程，并创建 workspace 把你的工程和 `Pods` 工程放在一起。只开 `.xcodeproj` 的话，`Pods` 工程和它的配置（xcconfig、framework 搜索路径）都不在，必然编不过。

**3. module 里的 `.ios/` 是什么？能改吗？**

那是 Flutter **自动生成的中转工程**，作用是产出 `Flutter.framework` / `App.framework` 供 CocoaPods 引用，同时让你能单独 `flutter run` 调试模块。

**不能改**——每次 `flutter build`/`pub get` 它都可能被重新生成，你的修改会丢。要改原生行为，改的是**宿主工程**（`WBiOSProject`），不是 `.ios/`。

**4. SwiftUI 为什么不能直接写 `FlutterViewController`？**

因为 `FlutterViewController` 是 **UIKit** 的 `UIViewController` 子类，而 SwiftUI 的视图体系是另一套（`some View`）。两者之间要靠官方桥接协议：

```swift
struct ColdFlutterPage: UIViewControllerRepresentable {
    func makeUIViewController(context: Context) -> FlutterViewController { ... }
    func updateUIViewController(_ vc: FlutterViewController, context: Context) {}
}
```

`UIViewControllerRepresentable` 就是"把一个 UIKit VC 包装成 SwiftUI View"的标准做法（对照 L6 的 `UiKitView`——那是反过来把原生 view 包进 Flutter）。

**5. 冷启动那段白屏是什么造成的？**

不传 `engine:` 时，`FlutterViewController` 会**当场新建并启动一个引擎**，这一过程包括：启动 Dart VM → 加载 `App.framework` → 执行 `main()` → `runApp` 建 widget 树 → 首帧渲染。在这套流程跑完之前，屏幕上没有 Flutter 内容可显示，于是就是白屏。L9 的预热就是把这段开销提前到 App 启动时。

**6. 冷启动路径为什么必须单独再挂一次 MethodChannel？漏了会怎样？**

因为 **MethodChannel 是绑定在"引擎"上的，不是全局的**——channel 的构造要传 `binaryMessenger`，而 messenger 属于某个具体引擎。预热引擎上挂的 handler，冷启动新建的那个引擎**看不到**。

漏了的现象：冷启动打开的 Flutter 页里，"要 token"没反应、"请宿主关闭"也没反应（Dart 侧收到 `MissingPluginException` 或调用无人应答）——因为这个页是 `fullScreenCover` 全屏盖住的，**用户被困在里面退不出去**。本课就实测踩到并修掉了这个问题。

**7. 对照 L4 的页面级混合，L8 根本不同在哪？**

**"谁 present 谁"完全对调了**：

| | L4 页面级混合 | L8 add-to-app |
|---|---|---|
| 宿主 | Flutter App | **原生 App** |
| 动作 | Flutter 调原生，原生 present 一个原生 VC（扫码页） | 原生 present 一个 **Flutter** 页 |
| 谁是"客人" | 原生页面 | **Flutter 页面** |
| 结果回传 | 原生把结果回给 Flutter | Flutter 把请求发给原生（要 token / 请求关闭） |

机制（MethodChannel、present/dismiss、延迟回值）是同一套，但**主客关系反过来了**——这正是 L8/L9 整个模块的认知主线。
