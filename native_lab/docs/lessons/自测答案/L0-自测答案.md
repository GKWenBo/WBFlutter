# L0 自测答案

**1. `Runner.xcworkspace` 和 `Runner.xcodeproj`，该用 Xcode 打开哪个？为什么？**

打开 **`.xcworkspace`**。工程一旦装了任何插件就会引入 CocoaPods，Pods 是一个独立的 project，只有 workspace 才同时含 `Runner` 和 `Pods` 两个 project 以及它们的依赖关系。单独开 `.xcodeproj` 会缺 Pods 的 target 和头文件搜索路径，编不过。这不是 Flutter 特有规矩，是 CocoaPods 通例（L8 接入 add-to-app 时会再遇到一次）。

**2. Release 包里，你写的 Dart 代码最终以什么形式存在于 .app 里？**

以 **AOT 编译出的 arm64 机器码**存在，打包成 **`App.framework`** 放进 `.app`；旁边是引擎本体 **`Flutter.framework`**。（Android 侧对应 `libapp.so` + `libflutter.so`。）

Debug 模式不一样：Dart 以 kernel snapshot（`.dill`）形式随包走，由引擎里的 **JIT** 执行——所以 Debug 才有热重载，Release 没有。

**3. Platform 线程和 UI 线程各自跑什么？哪条是 iOS 主线程？**

- **Platform 线程 = iOS 主线程**：跑原生代码、所有平台 API 调用、channel 的**原生侧** handler 回调。
- **UI 线程**：跑你写的**全部 Dart 代码**（root isolate）——build/layout/paint，产出图层树交给 Raster 线程。

另外两条是 Raster（栅格化上屏）和 IO（图片解码/纹理上传）。关键结论：**Dart 不在主线程跑**，所以 Dart ↔ 原生只能异步投递消息，这正是 MethodChannel 是 `Future` 而不是同步返回值的根本原因。

**4. 为什么改 App 显示名只动了 `Info.plist` 和 `AndroidManifest.xml`，一行 Dart 都不用改？**

因为"App 在桌面上叫什么名字"是**宿主平台的元信息**，由系统的包管理/桌面读取，跟 Flutter 引擎和 Dart 代码毫无关系：iOS 读 `Info.plist` 的 `CFBundleDisplayName`，Android 读 manifest 里 `application` 的 `android:label`。

这正好印证 L0 的主线认知——`ios/` 和 `android/` 就是两个完整的原生工程，凡是"原生工程该管的事"（显示名、图标、权限声明、Bundle ID、签名、部署目标）都在原生侧改，Dart 侧一行都不用动。顺带一提：`MaterialApp(title:)` 不是显示名，它只影响 Android 任务切换器里那张卡片的标题。
